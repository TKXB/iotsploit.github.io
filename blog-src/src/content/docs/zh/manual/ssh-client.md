description: 在 IoTSploit v0.0.19 中连接授权 SSH 主机，通过跳板主机访问目标，保持多个会话、保存密码，并通过 SFTP 传输文件。
---

**SSH Client** 提供交互式终端和 SFTP 文件传输，不要求系统另外安装 SSH 程序。它还可以通过串联的跳板主机访问目标，并同时保持多个会话。

本文以公开发布的 **v0.0.19** 为准。该工具可用于原生正式版、开发版和离线版，不会出现在 Web 版本中。

_依据：以下标签和行为均依据 IoTSploit UI **v0.0.19**（标签 `v0.0.19`，提交 `6bb8b5b`，2026-09-28）重新核对。_

:::danger[不会验证主机身份]
SSH Client 会显示服务器密钥指纹，但不会拒绝未知或已经变化的主机密钥。连接成功不能证明当前服务器就是预期目标。在输入凭据或敏感命令前，应使用可信网络，并把显示的指纹与管理员通过另一个可信渠道提供的值进行比较。
:::

## 连接前的准备

你需要：

- 已获授权的主机名或 IP 地址；
- SSH 端口，通常为 `22`；
- 用户名；
- 按需准备密码或 PEM 私钥；
- 预期的服务器密钥指纹；
- 经过批准的命令和文件传输计划；
- 使用跳板路由时，链路上每台机器的授权访问和凭据。

表单默认以 `root` 连接 `127.0.0.1:22`，请替换为你已获授权使用的主机。

应用最多保存五条最近使用的**路由**。一条路由是目标主机加上访问它所用的全部跳板主机，Recents 区域会先显示目标（`user@host via user@jump → user@jump`）。最近记录保存的是连接地址，而不是信任决定。凭据不属于最近记录，但你可以单独选择保存密码，见下文“保存的密码”一节。

## 连接主机

1. 打开 **Toolkit**。
2. 选择 **SSH Client**。
3. 输入主机、端口和用户名。
4. 选择认证方式：
   - **Password**
   - **Public Key**
   - **None**，仅适用于服务器明确允许的情况
5. 输入所需凭据。
6. 选择 **Connect**。
7. 继续操作前，把显示的服务器密钥指纹与管理员提供的可信值进行比较。

如果指纹不匹配，应立即断开。不要输入命令或传输文件。

### 通过跳板主机访问目标

打开 **Connect through a jump host** 开关，即可在目标前加入一个或多个跳板。每个跳板和目标使用相同的主机、端口、用户名和认证字段。选择 **Add another hop** 添加跳板；表单最多允许三个，达到上限后显示 **Three hops is the maximum.**。可以点跳板上的关闭按钮移除它，或关闭开关清空整条路由，改为直连。

表单上方的路由条按 `this device → Jump host 1 → … → Target` 的顺序显示，最外层在前，因此两个主机名不会混淆。跳板卡片标记为 **JUMP 1**、**JUMP 2**、**JUMP 3**，目标卡片标记为 **TARGET**。

一条链路会对每台主机分别登录，因此 **Connect** 会变成一个随各机器响应而填充的列表。每一行显示自己的角色和地址，标明当前处于等待、认证、已连接还是被拒绝，并给出该跳板耗时。连接过程中，各行会显示 `waiting to start`、`waiting for the hop before it`、`authenticating`、`authenticating through <hop>` 或 `connected`；从未尝试过的跳板标记为 `never contacted`。

客户端通过要求前一台主机打开 TCP 转发来访问下一跳，因此跳板主机必须允许转发。如果某台主机接受了登录但拒绝转发，错误会同时指出两端和可能的原因：

```text
root@10.0.0.1 will not forward to 10.42.0.7:22. Its SSH config may have
AllowTcpForwarding no, or 10.42.0.7 is not reachable from it.
```

请让管理员在该主机上允许 TCP 转发，或确认下一台主机可以从它访问。链路中的每台主机都作为自己进行认证，因此目标的凭据只会发给目标，不会交给跳板主机。

### 保护凭据

- 避免从共享剪贴板粘贴私钥。
- 不要在共享或不可信设备上使用该客户端。
- 在他人可能使用的设备上，保持 **Save password** 关闭；保存密码会降低该主机的保护。
- 确保终端日志和截图中没有密码、令牌或私钥内容。
- 完成任务后及时断开连接。

## 使用终端

连接后，页面会显示终端和连接状态。

像使用普通交互式 Shell 一样输入命令。命令使用当前认证账号的权限执行，可能修改或删除远程数据。

执行改变状态的命令前：

1. 确认当前提示符属于预期主机；
2. 确认当前目录；
3. 路径不明确可能造成破坏时，应使用绝对路径；
4. 保存仍需保留的文件或配置；
5. 确认命令属于批准的测试流程。

终端会适应窗口尺寸变化并支持普通交互输入。具体会话行为仍取决于远程 Shell、操作系统和账号配置。

## 使用多个会话

有会话打开时，连接表单会让位给会话堆栈。在桌面端，左侧栏在 **OPEN · N** 下列出打开的会话；在手机端，应用栏会多出一个 **New session** 按钮，并且一次只显示一个终端。应用栏的状态标签显示 **● N connected**，没有活动会话时显示 **Disconnected**。

- **New session** 重新打开连接表单，不会关闭任何会话。
- **Back to sessions** 从表单返回终端。
- **Expand all** 和 **Collapse all** 一次展开或折叠所有面板。
- 点面板标题可折叠或展开该面板，**Show only this session** 会折叠其余面板。
- 折叠后的面板仍会显示最后一行输出，以及在折叠期间打印的行数。
- **Disconnect**（退出图标）结束会话并移除面板；**Close** 移除已经结束的会话面板。
- **Disconnect all** 经确认后结束所有打开的会话。

会话属于整个应用：离开 SSH Client 页面不会结束会话，在别的页面或面板折叠期间到达的输出也会保留。只有主动断开、关闭面板或退出应用时，会话才会结束。

## 理解工作目录显示

CWD 指示器会尝试跟随远程 Shell 的当前目录。在能够提供所需进程信息的 Linux 目标上，自动跟随效果最好。

如果显示的目录缺失或过期：

- 选择 CWD 指示器并手动输入路径；
- 关闭再打开跟随模式；
- 传输文件前在 Shell 中使用 `pwd` 确认目录。

上传或下载前，不能只依赖 CWD 指示器判断路径。

## 使用 SFTP 传输文件

:::caution[核对来源和目标路径]
上传可能替换远程已有文件，下载也可能在本机创建或替换文件。开始传输前应核对两端路径，并保存重要数据。
:::

### 上传

1. 确认远程工作目录。
2. 选择 **Push**。
3. 选择一个或多个本地文件。
4. 核对所选文件名。
5. 开始传输并等待完成。
6. 检查远程文件大小或哈希。

### 下载

1. 确认远程工作目录。
2. 选择 **Pull**。
3. 选择远程文件。
4. 按提示选择本地位置。
5. 等待传输完成。
6. 使用文件前检查本地文件大小或哈希。

Cancel 会停止应用对传输的处理。取消或中断后，应检查两端是否留下临时文件或不完整文件。

## 保存的密码

默认不保留密码。若要保留，请在连接前为对应主机打开 **Save password**；一条链路中的每台主机（包括跳板）都有各自的开关。只有在整条链路完成认证后才会写入密码，因此输错的密码不会被保存，并且仅适用于使用 **Password** 方式的主机。

密码保存到哪里取决于本机：

- **操作系统钥匙串。** 通常情况下，密码保存在操作系统的钥匙串中（Keychain、Keystore、DPAPI 或 libsecret）。
- **加密文件。** 如果没有可用的钥匙串（例如没有 Secret Service 的 kiosk 树莓派），开关仍然可用，但密码会以 AES-256-GCM 加密后保存在应用数据目录下的文件中。表单会提示：**No system keyring found. The password will be saved encrypted in the app's data folder.** 密钥与被加密的文件放在一起，因此它只能避免明文文件和随意翻找，除此之外没有更多保护：能读取你文件的人也能读取这些密码。

保存的密码按主机（`user@host:port`）而非按路由保存，因此某个跳板保存的密码可用于所有经过它的路由。选择最近路由时，会为其中的每台主机恢复已保存的密码；密码字段在仍保存原值时显示钥匙标记，输入新值后即改用新值。把某台主机临时切换到公钥或免认证方式，不会删除它已保存的密码。

Recents 区域的 **Forget saved passwords** 会打开 **Forget saved passwords?** 对话框。确认后会移除本设备上保存的所有 SSH 密码；最近连接记录会保留。

## 断开连接

完成后选择 **Disconnect**，并确认：

- 没有命令仍在运行；
- 没有活动传输；
- 所需输出已经保存；
- 临时文件和敏感文件已经按测试计划处理。

## 使用限制

- 显示服务器主机密钥，但不会强制验证。
- 没有面向用户的端口转发控制。客户端在内部使用 TCP 转发，通过跳板主机访问目标，而跳板主机可以拒绝转发。
- 最多串联三个跳板主机，最多记住五条路由。
- CWD 自动跟随在 Linux 目标上最可靠。
- 最近记录只保存连接信息，不代表信任决定，并与任何已保存的密码分开。
- 文件传输行为取决于远程 SFTP 服务和本地平台。
- 会话在离开页面后仍然保留，但会在应用退出时结束。

## 故障排查

### 连接超时

检查主机、端口、路由、防火墙、VPN 和服务器状态。使用跳板路由时，检查进度列表中提到的跳板：始终没有到达 `connected` 的跳板会中断整条链路。

### 跳板主机拒绝转发

错误会指出拒绝转发的跳板以及它无法访问的主机，并提示 `AllowTcpForwarding no`。请让管理员在该主机上允许 TCP 转发，或确认下一台主机可以从它访问。客户端无法绕过禁止转发的服务器。

### 保存的密码被拒绝

消息可能以 **saved password may be out of date** 结尾。关闭 **Save password** 并输入当前密码连接，或使用 **Forget saved passwords** 后重新输入。在被拒绝之后，保存的密码只会在连接成功时才被覆盖。

### 认证失败

确认用户名和认证方式。使用公钥认证时，确认 PEM 私钥与服务器授权的公钥匹配。在使用链路时，错误会指出失败的主机。

### 指纹发生变化

立即停止操作，并请管理员确认服务器密钥是否被有意更换。不要只根据当前连接接受变化。

### 连接成功但没有提示符

按一次 Enter，然后确认该账号具有交互式 Shell。部分受限账号只允许 SFTP。

### 上传或下载失败

检查 SFTP 是否可用、远程权限、可用空间、所选目录，以及是否存在同名文件。
