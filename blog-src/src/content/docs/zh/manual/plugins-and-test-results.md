**Plugins** 区域用于浏览单个测试、把插件组织成执行组，以及查看历史结果。需要比 Control Panel 中的简洁执行器更多信息或组织能力时，可以从这里开始。

本文以公开发布的 **v0.0.19** 为准。

_依据：以下标签和行为均依据 IoTSploit UI **v0.0.19**（标签 `v0.0.19`，提交 `6bb8b5b`，2026-09-28）重新核对，来源为 `lib/screens/plugins/` 下的源码。_

:::caution[执行前先检查]
插件可以通过已配置的服务器与网络、设备、固件和文件交互。只运行可信插件，并且只对已获授权的活动目标执行。启动前检查参数；修改插件源码后，还应先完成代码审查。
:::

## 开始前的检查

确认：

- IoTSploit API 和 WebSocket 服务可用；
- 当前目标是正确的目标；
- 插件说明符合本次测试目的；
- 在提供当前页面的主机上，所需驱动和硬件已经就绪；
- 已经确定如何保留和解释结果。

服务端只保留一个**当前目标（current target）**，本页面与应用其他部分读写的是同一个目标。请在页面顶部的 **Target** 下拉框中选择。

## 查找插件

1. 打开 **Plugins** → **Plugin List**。
2. 检查 **Target** 下拉框，选择已获授权的测试系统。
3. 按插件名称、说明、作者或版本搜索。搜索生效时，列表上方会显示匹配数量，并提供 **Clear search** 操作。
4. 查看插件详情。

窗口较宽时，插件以表格显示，列为 **Plugin Name**、**Version**、**Author**、**Description** 和 **Actions**；窗口较窄时改为卡片。视图切换按钮可在网格和列表之间切换。

### 无法在当前主机运行的插件

如果插件无法在提供当前页面的主机上运行，名称旁会出现红色 **Unavailable** 标记——窄卡片中只显示一个禁止图标——其执行操作同时被禁用。把鼠标悬停在标记上，可查看服务端给出的原因，以及在提供时给出的修复提示。

可用性是提供本次响应的后端主机的属性，而不是插件的全局属性：在这里被阻止的插件，仍可能在另一台主机上运行。它会在每次加载列表时重新读取，并由执行器在运行前再次解析，且不会被缓存。

### 空后端与加载中

首次加载时列表会显示加载指示器。如果后端返回零个插件，页面会显示 **No plugins available** 和 **Refresh** 操作，这不同于搜索无结果时的 **Clear search**。空状态是该主机的真实回答，不代表页面仍在加载。

## 运行单个插件

1. 确认 **Target** 下拉框中的当前目标。
2. 选择插件的 **Execute**。
3. 如果出现 **Enter Parameters** 对话框，检查每个值。
4. 默认值不属于当前实验环境时，应先替换。
5. 在对话框中选择 **Execute** 开始运行，或选择 **Cancel** 在运行前退出。
6. 等待最终状态。

参数对话框与 Control Panel 使用的是同一个：它会按照每个参数的声明来呈现——声明的选项显示为可选项，整数保留声明的范围，true/false 标志显示为菜单，列表以逗号分隔文本输入。插件标记为必填的字段必须在运行前填写，超出范围的值会在对话框仍未关闭时被拦截。

如果插件的输入需要依据目标自身的定义组合一个 CAN 帧，会打开 CAN 编辑器而不是普通表单。该流程需要当前目标，请先设置。

### 会提问的插件

部分插件会在运行中停下来向操作者提问。Plugin List 没有回答这些问题的界面，因此这类插件的操作显示为 **Interactive**，选择它只会弹出 **Run this in the Control Panel** 提示，而不会启动运行。请打开 [Control Panel](/blog/zh/manual/control-panel-workflow/)，在那里启动插件，问题会内嵌显示在 Execution 日志中。

部分插件会立即返回；另一些插件在后台运行，并通过 WebSocket 报告进度；运行期间其操作变为 **Stop**。

异步运行期间选择 **Stop**，v0.0.19 只会停止界面对该任务的跟踪，不会取消服务器任务。需要真正终止操作时，应使用实验室的服务器端停止流程。

## 解释结果

插件结果可能包含：

- 成功或失败状态；
- 便于阅读的消息；
- 插件生成的其他数据；
- 所选目标和执行时间。

成功的含义由具体插件决定。它可能只表示请求完成、设备有响应，或检查满足某个条件。IoTSploit 不会自动把每个成功结果判定为漏洞。

重要发现应结合目标文档、可重复证据和专业判断进行验证。

## 查看 Test Results

打开 **Plugins** → **Test Results**，或在 Plugin List 上选择历史记录操作。

列表包含 **Date/Time**、**Plugin**、**Status**（Success 或 Failure）、**Message** 和 **Actions** 列。你可以：

- 按插件、消息或目标搜索；
- 按日期、插件或状态排序；
- 打开完整消息和返回数据；
- 确认后删除单条结果；
- 确认后清空所有已保存结果。

v0.0.19 的历史结果保存在当前应用配置中，不是服务器审计日志。结果不会自动同步到其他设备。清除应用数据或卸载应用可能删除历史。

删除前，应先保存测试任务要求保留的证据。向其他人分享结果前，应移除秘密、凭据、客户数据和可识别设备的信息。

## 创建插件组

插件组按你定义的顺序运行多个插件：

1. 打开 **Plugins** → **Plugin Groups**。
2. 选择添加操作，打开 **Create Plugin Group**。
3. 输入 **Group Name** 和有意义的 **Description**。
4. 在 **Select Plugins** 下只勾选属于同一授权工作流的插件。
5. 使用所选插件上的设置操作，设置其 **Execution Sequence** 以及是否 **Ignore Failures**。
6. 选择 **Create**。缺少组名或未选父组时，错误会显示在对应字段下方，而不是藏在对话框后面。
7. 如需把该组放入另一个组，选择 **Nest under another group**，选择 **Parent Group**，并设置其 **Parent Relationship Settings**——**Sequence**、**Ignore Failures** 和 **Force Execution**。

插件组列表显示每个插件的 **Seq: N**，设置了时还会显示 **Ignore Fail** 标签；嵌套组显示在父组之下。结构应保持清晰，让其他测试人员在执行前能够理解顺序和失败处理方式。

### 安全地运行插件组

执行前：

- 确认当前目标；
- 检查每个已启用插件；
- 检查参数和硬件前提；
- 确认失败后是否继续；
- 评估整个序列对目标的综合影响。

在插件组卡片上选择 **Execute group**。v0.0.19 的插件组没有异步单插件那样的实时进度流。页面长时间没有变化，不代表服务器没有继续工作。

## 编辑插件源码

**Edit Plugin** 操作会在编辑器中打开服务器提供的插件源码。保存后，服务器后续执行的测试行为可能发生变化。编辑器会标记未保存的改动，在有内容可保存前保持 **Save** 禁用，并在存在未保存修改时离开前询问 **Discard unsaved changes?**。

只有满足以下条件时才应修改：

- 已获授权修改服务器端测试代码；
- 原始源码已纳入版本控制或完成备份；
- 其他人员可以审查改动；
- 可以先在隔离目标上验证。

v0.0.19 的上传操作只是占位：它会提示 **Plugin upload coming soon**，不是完整的插件安装流程。

## 故障排查

### 插件列表无法加载

检查 API 地址和服务器状态。首次加载会显示加载指示器；如果一直停留，说明后端不可达。如果其他依赖服务的页面也失败，请返回 Settings。

### 列表没有插件

**No plugins available** 表示后端返回了空列表，而不是仍在加载。请确认该主机上的插件目录已填充，然后选择 **Refresh**。

### Execute 不可用

查看插件名称旁的 **Unavailable** 标记，并将鼠标悬停其上以读取服务端原因和提示。插件要么加载失败，要么其要求在当前主机上未满足——请检查服务器日志，硬件插件还需检查该主机的驱动。同时确认已设置当前目标。

### 插件需要先回答才能运行

标记为 **Interactive** 的插件无法从 Plugin List 启动。请打开 **Control Panel** 并在那里运行，问题会内嵌显示。

### 无法连接实时进度

检查 WebSocket 地址和防火墙规则。服务器任务可能已经开始，重试前先确认服务器状态。

### Test Results 中没有结果

等待最终状态，刷新页面，并确认当前使用的是运行插件时的同一应用配置。

### 插件组提前停止

检查执行顺序和失败设置。未设置为忽略失败的插件可能会终止后续序列。
