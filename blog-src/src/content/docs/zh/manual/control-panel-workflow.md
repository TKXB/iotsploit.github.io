**Control Panel** 是从准备测试目标到获得插件结果的最短路径。目标/设备选择、驱动状态、插件执行和日志都集中在同一工作区。

本文以公开发布的 **v0.0.19** 为准。

_依据：以下标签、控件和状态均依据 IoTSploit UI **v0.0.19**（标签 `v0.0.19`，提交 `6bb8b5b`，2026-09-28）重新核对，来源为 `lib/screens/control_center/` 和 `lib/l10n/` 下的源码。_

:::caution[仅在获得授权时使用]
插件可能读取数据、产生网络流量、发送硬件帧、重置设备或改变设备状态。运行前先阅读插件说明和参数，并且只使用已获授权的目标。
:::

## 开始前的检查

确认：

- API 和 WebSocket 地址已经配置；
- 侧边菜单底部的 **Backend** 状态显示 **Online**；
- 目标已经存在，或你已经准备好创建目标所需的信息；
- 所需适配器或设备连接到隔离的实验环境；
- 你了解所选插件预期执行的操作。

**Backend** 状态栏位于侧边菜单底部。状态标签会显示 **Checking**、**Online**、**Degraded**、**Version mismatch** 或 **Unreachable**，下方一行显示服务地址和版本。点击状态栏可以查看详情、执行 **Check now** 或跳转到 **Server settings**。没有后端的构建（例如 Offline Toolkit）不会显示状态栏。

如果页面无法连接，请先阅读[连接 IoTSploit 服务](/blog/zh/manual/server-and-build-setup/)。

## 设置当前目标

服务端只保留一个**当前目标（current target）**。插件执行和 CAN 编辑器都作用于它，因此设置目标和阅读目标是两个分开的步骤。

1. 打开 **Control Panel**。
2. 在左侧 **Assets** 列表的 **Targets** 分组中选择已获授权的测试系统。此操作只会在右侧 **Details** 面板显示详情，不会改变当前目标。
3. 在 **Details** 中选择 **Set as current**。如果该目标已经是当前目标，该位置会显示 **CURRENT TARGET** 标记。
4. 确认插件表格标题栏现在显示目标名称。未设置时显示 **No current target**。

该选择在整个应用中共享：**Targets** 列表的 **Current** 列、目标浏览器标题栏和 **Plugins** 页面读写的是同一个当前目标。**Assets** 列表中，当前目标带有 **TARGET** 标签。

未设置当前目标或已有插件正在运行时，**Execute** 操作不可用。如果所需目标不存在，请先在 **Targets** 中创建，再返回 Control Panel。

## 准备驱动和设备

部分插件需要硬件驱动。只有至少检测到一个连接设备的驱动才会出现在 **Assets** 列表的 **Devices** 分组中。

1. 选择所需的驱动条目。
2. 在 **Details** 中查看 **Status**（**ENABLED** 或 **DISABLED**）和 **Connected** 数量。
3. 选择 **Enable driver**。测试完成后选择 **Disable driver**。
4. 如果驱动提供设备命令，首次检查优先选择只读的识别命令。

不要为了清除错误而启用无关驱动。缺少硬件或权限时，插件即使开始运行，也可能在后续步骤失败。

## 选择插件

插件表格列出 **PLUGIN NAME**、**VERSION**、**AUTHOR**、**DESCRIPTION** 和 **ACTIONS**，并提供一个按名称、说明或作者匹配的搜索框。

阅读插件说明，并确认：

- 插件是否成功加载；
- 所需参数；
- 插件说明中的目标或硬件前提。

加载失败的插件会在 **DESCRIPTION** 列显示原因，其 **Execute** 操作不可用。此时应查看服务器日志，而不是反复点击执行操作。

## 运行插件

1. 在插件行上选择 **Execute**。
2. 如果出现 **Enter Parameters** 对话框，检查每个字段。对话框会显示声明的选项、范围和单位，必填字段未填写时会在运行前提示。
3. 示例值或默认值不符合实验环境时，应先替换。
4. 在对话框中选择 **Execute** 开始运行，或选择 **Cancel** 在运行前退出。
5. 观察 **Execution** 日志和状态条。

部分插件会立即返回结果，另一些插件在后台继续运行，并把进度发送到页面。最终状态出现前，应保持应用与服务的连接。

### 回答运行中插件的问题

部分插件会在运行中停下来向操作者提问。问题不是对话框，而是以内嵌形式出现在 **Execution** 日志中：橙色卡片标题为 **WAITING FOR YOUR INPUT**，服务器设置了截止时间时会显示倒计时。

- 填写字段，或选择给出的选项。
- 选择 **Submit**（是/否问题会改为显示自身的确认和拒绝标签）。
- 选择 **Cancel run**，让服务器取消本次运行，而不是回答问题。
- 状态条会同时显示剩余时间和 **Jump to question** 控件，因为日志滚动后提示会移出视野。

回答后，问题会就地折叠成一条日志行，运行继续。连接中断时，卡片显示 **RECONNECTING** 并禁止发送，直到连接恢复；运行本身仍在服务器上继续，页面重新连接或刷新后会恢复未回答的问题。

## 理解执行状态

| 状态 | 含义 |
|---|---|
| Running | 操作已经开始，或页面正在接收进度 |
| Waiting for your input | 插件提出问题并被阻塞，等待回答 |
| Completed | 插件完成并报告成功 |
| Failed | 插件、连接或结果处理报告错误 |
| Cancelled | 运行在完成前被取消 |
| Lost | 负责运行的 worker 已退出 |

**Completed** 只是插件状态，不是安全结论。应阅读消息和结果数据，再与目标的预期行为比较。

### 停止运行

对于异步运行，选择 **Stop** 只会关闭当前页面正在观察的数据流，并把该行标记为 **Stopped by operator**；它不一定会取消服务器上已经开始的任务。服务器任务仍可能继续与目标交互。

对于正在等待回答的运行，请使用问题卡片上的 **Cancel run**，由服务器取消该次执行。

如果测试必须立即停止，请使用实验室的服务器端停止流程，或在确保安全的前提下隔离目标。不要把界面中的操作当作紧急停止功能。

## 查看日志

**Logs** 卡片有两个标签页：

- **Execution** 显示当前插件运行的记录，包括其中提出的问题。
- **System** 在 **Console Logs** 标题下显示更广泛的服务器活动。

插件失败时先看 **Execution**。问题涉及服务器、驱动、设备连接或多个操作时，再查看 **System**。复制和清除图标作用于 Execution 记录。

**Logs** 卡片可以相对插件表格调整大小：拖动两张卡片之间空隙中的手柄，双击手柄可恢复为平均分配。每个窗口都保留最小高度。在窄布局中两张卡片纵向堆叠，不显示分隔手柄。

日志可能包含目标地址、设备标识、文件名或插件输出。把日志复制到问题报告或发送给授权团队之外的人之前，应先移除敏感信息。

## 查看保存结果

完成和失败的插件结果会保存在当前应用配置中，可从 **Test Results** 打开。结果通常包含插件、时间、目标、状态、消息以及插件返回的其他数据。

结果只保存在当前应用配置中。清除应用数据或卸载应用可能删除历史结果。清理前，请按照实验流程导出或记录需要保留的证据。

## 故障排查

### 页面显示后端连接错误

先查看侧边菜单底部的 **Backend** 状态，再打开 **Settings** 确认两个服务器地址。横幅会指出失败原因——**Connection refused**、**Request timed out**、**Host not found**、**Network unreachable** 或某个 HTTP 状态——并提供 **Retry** 和 **API settings**。如果普通数据可以加载，但没有实时进度，请检查 WebSocket 地址和防火墙规则。

### 插件执行器提示设置当前目标

在 **Assets** 中选择目标，并在 **Details** 中点击 **Set as current**。未设置前，插件表格标题栏显示 **No current target**。如果选择无法保留，请确认 API 连接，并在 **Targets** 页面重新设置。

### 无法启用所需驱动

检查物理连接、操作系统权限和服务器端驱动安装。在正确设备被检测到之前，不要继续运行硬件插件。

### 插件一直显示 Running

检查 **System** 日志和后端状态栏。WebSocket 连接中断后，即使服务器端状态已经变化，页面也可能收不到最终消息。

### 插件显示 Failed

先阅读完整消息，再检查目标、参数、驱动状态和服务连接。失败信息用于诊断，不能直接证明存在漏洞。
