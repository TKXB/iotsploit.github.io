IoTSploit 是一款用于物联网安全测试的 Flutter 应用。正式版本结合了后端驱动的控制面板、基于插件的测试执行、协议模糊测试器和一组独立的工具包工具。部分工具在本地运行，部分需要配置后端，还有部分依赖硬件适配器或托管的 Web 应用。

本指南梳理应用中用户可见的功能区域、正式版、开发版和离线版之间的差异，以及连接各部分的工作流。在阅读具体功能手册之前，先用它找到适合当前任务的入口。

:::caution[仅在获得授权时使用]
与设备、网络、固件或调试接口交互的测试功能，需要拥有目标或获得明确授权。扫描、模糊测试和命令执行工具可能影响你不拥有的系统。在使用任何测试功能前，请先确定实验室范围和授权边界。
:::

## 证据与范围

本指南中的功能清单依据应用源码（提交 `c3f20ff8`，版本 `0.0.17+17`）和正式版本的配置进行核实。公开下载页面当前分发版本为 `0.0.16`。当源码行为与已发布版本可能存在差异时，相关手册会明确说明证据范围。不要把仅存在于开发版本的路由、未连接的界面或打包的资源当作已发布功能的证明。

## 三种应用版本

IoTSploit 有三个版本（flavor），每个版本启用不同的页面和工具。版本在构建时选定，运行时无法更改。

| 版本 | 应用标题 | 起始页 | 用途 |
|---|---|---|---|
| 正式版（prod） | IoTSploit | 控制面板 | 面向已发布测试流程的完整功能集 |
| 开发版（dev） | IoTSploit Dev | 控制面板 | 所有页面，包括实验性和仅开发版界面 |
| 离线版（offline） | Toolkit | 工具包 | 无需后端的独立本地工具 |

## 正式版导航

正式版的侧边菜单按以下顺序显示这些顶层区域：

1. **控制面板** — 目标和设备清单、插件运行器，以及流式执行日志。
2. **工具** — 实用工具界面，包括 USBTMC 仪器控制。
3. **插件**（可展开分组）：
   - **插件列表** — 浏览并运行单个插件。
   - **插件组** — 将插件组织为有序分组。
   - **测试结果** — 查看插件运行的已保存结果。
4. **工具包** — 独立于插件系统运行的独立工具。
5. **驱动程序** — 启用、禁用和检查硬件驱动及已连接设备。
6. **目标** — 创建、编辑、选择和删除测试目标。
7. **模糊测试** — 配置、管理和运行协议模糊测试活动。
8. **威胁建模** — 内嵌的攻击路径分析应用（仅在 macOS、Web 和 Windows 上可用）。
9. **设置** — 服务器配置、语言、主题、日志和版本信息。

以下区域存在于源码中，但**不**属于正式版本：**AI 助手**、**JTAG 边界扫描**、**组件展示**和**版本对比**。它们仅用于开发，在发布版本中隐藏。

## 离线版导航

离线版是一个精简应用，标题为 "Toolkit"。其侧边菜单仅显示：

1. **工具包** — 与正式版相同的工具网格，但过滤为无需后端即可运行的工具。
2. **设置** — 应用设置。

离线版工具包网格中仅显示标记为可离线运行的工具：**文件混淆**、**密钥工具**、**端口扫描器**和 **SSH 客户端**。CAN 分析、GreatFET 扫描、ESP32 测试、Ubertooth BLE/Bt 和公网 IP 等依赖后端的工具会被隐藏。

## 工具包可用性矩阵

工具包网格根据版本和平台显示不同工具。仅当版本启用了工具包页面、且工具的可用性标志允许时，该工具才会出现。

| 工具 | 离线版 | 正式版 | 需要原生构建（不支持 Web） |
|---|---|---|---|
| 文件混淆 | 是 | 是 | 否 |
| 密钥工具 | 是 | 是 | 是 |
| 端口扫描器 | 是 | 是 | 是 |
| SSH 客户端 | 是 | 是 | 是 |
| GreatFET 扫描 | 否 | 是 | 否 |
| CAN 分析 | 否 | 是 | 否 |
| ESP32 测试 | 否 | 是 | 否 |
| Ubertooth BLE/Bt | 否 | 是 | 否 |
| 公网 IP | 否 | 是 | 否 |
| 逻辑分析仪 | 否 | 否（仅开发版） | 否 |
| FTDI UART | 否 | 否（仅开发版） | 是 |

标记为"需要原生构建"的工具使用了在 Web 构建中不可用的 Rust 桥接。Web 构建会自动隐藏这些工具。

## 平台限制

两项平台检查会影响用户能打开哪些功能：

- **威胁建模**使用内嵌 WebView（`flutter_inappwebview`）。仅在 macOS、Web 和 Windows 上可用。在不支持的平台上，菜单项会被隐藏。
- **依赖 Rust 的工具**（密钥工具、端口扫描器、SSH 客户端、FTDI UART）需要原生构建。Web 构建会隐藏它们，因为 Rust 桥接不可用。

## 工作流如何连接

正式版的主要区域构成了一条从范围定义到结果审查的工作流：

1. **定义目标** — 在**目标**中创建记录被测系统的目标。
2. **检查驱动和设备** — 在**驱动程序**中启用硬件驱动并确认已连接设备。
3. **选择目标** — 在**控制面板**中选择目标，该目标将接收插件执行。
4. **选择插件** — 在**控制面板**或**插件**中查看其参数和描述。
5. **执行** — 插件在后端运行；异步运行通过 WebSocket 流式传输进度。
6. **查看结果** — 在**测试结果**中查看已保存的完成和失败运行记录。

**工具包**和**模糊测试**独立于此插件工作流。工具包工具在本地运行或针对直接指定的目标运行。模糊测试有自己的配置、测试管理、活动和结果区域。

## 本地、依赖后端和依赖硬件的功能

了解每个功能在哪里运行，有助于选择合适的版本并准备前置条件。

**本地工具**在设备上运行，不需要后端服务器。离线版中包括：文件混淆、密钥工具、端口扫描器和 SSH 客户端。文件混淆和公网 IP 仅在可选上传或查询时使用 HTTP，核心操作不依赖网络。

**依赖后端的功能**需要可访问的 API 和 WebSocket 服务器。包括控制面板、目标、驱动程序、插件、插件组、测试结果和模糊测试。这些页面在打开时从后端加载数据，服务器不可达时会显示连接错误横幅。

**依赖硬件的功能**需要物理适配器、驱动或设备。CAN 分析需要 SocketCAN 接口；Ubertooth BLE/Bt 需要 Ubertooth One 硬件；GreatFET 扫描需要 GreatFET 板；ESP32 测试连接到已配置的 ESP32 设备；USBTMC 仪器控制需要 USB 连接的仪器；FTDI UART 需要兼容的 FTDI 芯片。

**托管功能**在通过 WebView 内嵌的外部 Web 应用中运行。威胁建模内嵌了攻击路径分析应用。其数据存储、模型配置和导出行为由该托管应用定义，而非本地 IoTSploit 构建。

## 从哪里开始

- 要对目标运行授权的插件测试，从[控制面板工作流](/blog/zh/manual/control-panel-workflow/)开始。
- 要配置 API 和 WebSocket 服务器，从[服务器与构建配置](/blog/zh/manual/server-and-build-setup/)开始。
- 要使用独立的本地工具，打开[工具包](/blog/zh/manual/key-tool/)并选择一个工具。
- 要运行协议模糊测试，从[IoT 模糊测试配置](/blog/zh/manual/iot-fuzzer-configuration/)开始。
- 要进行攻击路径建模，在受支持的平台上打开**威胁建模**。

## 可用性与限制

- 正式版是已发布的功能集。开发版和离线版暴露不同的页面和工具；不要假设仅开发版的功能在已发布版本中可用。
- Web 构建不支持依赖 Rust 的工具。请在原生桌面版本中使用密钥工具、端口扫描器和 SSH 客户端。
- 威胁建模在不支持 WebView 的平台上不可用。
- 依赖硬件的工具需要所指明的硬件和平台驱动；工具出现在网格中并不证明硬件已连接。

## 推荐的下一步

安装正式版，打开**设置**，确认 API 和 WebSocket 服务器地址可访问。然后打开**控制面板**，确认目标和插件能正常加载。如果连接失败，请先按照[服务器与构建配置](/blog/zh/manual/server-and-build-setup/)完成配置，再运行任何测试。
